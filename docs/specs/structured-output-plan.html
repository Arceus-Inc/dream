dream · agentic principles

Why structured output

Agents don’t just chat — they hand typed contracts across boundaries. Today dream enforces those contracts after the model speaks. Native response_format enforces them while it speaks.

Agentic principles this touches

Modern harnesses separate “do work with tools” from “emit a machine-checkable artifact.” Structured output is the second half of that contract.

01 · contracts at boundaries

Handoffs must be typed

Planner → generator, evaluator → sprint ledger, subagent → parent: each seam is a protocol. If the artifact is free-form prose, the next stage guesses. If it’s JSON Schema, the next stage can branch, score, or fail deterministically.

02 · constrain at decode

Don’t rely on manners

Prompting “return only JSON” is soft. Provider response_format: json_schema is hard — the sampler is biased (or constrained) toward valid structure. Post-hoc repair is a safety net, not the primary control.

03 · act-loop ≠ typed complete

Two different jobs

The act-loop (tools, multi-turn, refunds, spawn) is for exploration and side effects. A structured complete is for producing one schema’d object. Using a full agent session to emit a verdict is overkill and less reliable than a one-shot constrained decode.

04 · DoD must fail closed

Graders aren’t advisors

Research handoffs can fail-open (parent keeps working with a warning). Definition-of-done graders (api_verifier, test_author) must not. A best-effort malformed verdict that looks like a pass is worse than a loud error.

05 · cost & turn budget

Repair burns real turns

Every free-form repair session is another model call, another chance to drift, another hit to max_turns / latency. Constraining the first decode cuts repair rate and keeps IterationBudget for real work.

06 · eval-first

Outcomes you can score

Agentic engineering wants measurable completion criteria. Structured ledgers and verdicts are evaluable (schema valid? fields present? score ≥ threshold?). Prose envelopes are brittle evals dressed as JSON.

Two kinds of agent work

Confusing them is why “just prompt harder” keeps failing on planner/evaluator heads.

Act-loop work

Open-ended. Tools. State changes. Bounded by turns / IterationBudget.

  • generator implementing a sprint
  • execute_code / spawn_subagent
  • browser research, file edits, tests
vs

Typed-complete work

Closed form. One object. Bounded by schema validity.

  • planner ledger / evaluator verdict
  • subagent return contracts
  • repair / reformat passes
Reliability
Schema ≫ hope

Constrained decode fails less often than “please emit JSON” + regex scrape.

Cost
Fewer repair turns

First attempt valid → skip 1–2 reformatter sessions per handoff.

Safety
Fail posture matters

Open for scouts; closed for DoD. Same schema machinery, different exit.

What we have today

Dream is strong on tool inputs and post-hoc output checks. It does not yet ask the provider to constrain decode.

In place · soft / post-hoc

  • Tool input schemas Pydantic → JSON Schema on the way into tools. Model must call tools with valid args. BaseTool.input_schema · tag have have
  • Subagent output_schema After the child finishes: coerce JSON → jsonschema → ≤2 free-form repair sessions → fail-open. enforce_output_schema · chorus specialists post-hoc
  • Role heads + ask_until_parsed Planner/evaluator prompted for XML/JSON envelopes; re-prompt on parse failure. Still unconstrained decode. _planner_head · _evaluator_head · _head_retry prompt + parse
  • ToolResult.structured Tools can return machine-readable payloads to the loop — not model final answers. have

Missing · native constrain

  • response_format on the wire No json_schema / json_object in request bodies. Azure/OpenAI-compat already supports it for many models. gap
  • Thin complete_structured No one-shot helper for “messages + schema → {text, parsed}”. Everything goes through agent sessions. gap
  • Heads on constrained decode Ledger/verdict still depend on prose manners + retry. Highest leverage for run_task. gap
  • Fail-closed for verifiers DoD graders inherit fail-open. A bad JSON verdict can soft-land as best-effort. gap

Why this gap hurts in practice

Chorus employees already declare schemas on specialists (researcher, strategist, api_verifier, …). The contract exists — enforcement is late and polite. That violates the agentic rule: machine-checkable done conditions at the earliest boundary, not after two repair turns.

Hermes’s bar isn’t “more JSON.” It’s constrain at decode for typed completes, validate, then repair. OpenHarness isn’t ahead here either. Dream’s catch-up is specifically that decode seam plus fail posture for DoD.
